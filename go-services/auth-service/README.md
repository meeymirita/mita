# auth-service — настройка и сборка

Краткое руководство по настройке сервиса, исправлениям при сборке и роли конфигов.

---

## Что было сделано при настройке

1. **Исправлены имена пакетов**  
   В `internal/email`, `internal/models`, `internal/queue` был объявлен один и тот же пакет `internal`. В одном модуле не может быть несколько пакетов с одним именем. Имена приведены к именам папок: `package email`, `package models`, `package queue`.

2. **Обновлён `cmd/send-code/main.go`**  
   Вызовы заменены на правильные: `queue.ConnectRabbit()`, `models.VerificationMessage`, `email.SendEmail()`. Добавлен импорт `"fmt"` для `fmt.Println`.

3. **Настроен Dockerfile**  
   Используется образ Go 1.25 (для совместимости с `air@latest`). Команда сборки передаётся в air через аргументы CLI, чтобы путь к пакету `./cmd/send-code` не терялся при парсинге toml.

4. **Настроен `air.toml`**  
   Задан `root = "/app"`, `tmp_dir = "tmp"`, `pre_cmd` для создания каталога `tmp`, `entrypoint` для бинарника. Команда сборки задаётся в Dockerfile через `--build.cmd`, а не в toml.

5. **Добавлен `go.sum`**  
   В репозитории не было `go.sum`, из-за чего сборка падала с «missing go.sum entry». Файл создан с контрольными суммами для `github.com/rabbitmq/amqp091-go v1.10.0`.

6. **Добавлен `build.sh` (опционально)**  
   Скрипт для ручной сборки из `/app`: `cd /app && go build -o /app/tmp/main ./cmd/send-code`. Сейчас сборка вызывается через air CLI, скрипт можно использовать для отладки или ручного билда.

## go.mod и go.sum

### go.mod

- **Назначение:** определяет **модуль** Go: его имя, версию языка и список прямых зависимостей.
- **Содержимое здесь:**
  - `module auth-service` — имя модуля (используется в импортах: `auth-service/internal/queue`).
  - `go 1.22` — минимальная версия Go для этого модуля.
  - `require github.com/rabbitmq/amqp091-go v1.10.0` — прямая зависимость и её версия.
- **Зачем:** без `go.mod` проект не считается модулем, импорты вида `auth-service/...` не работают, зависимости не версионируются.

### go.sum

- **Назначение:** хранит криптографические **контрольные суммы** (хеши) скачанных модулей и их `go.mod`.
- **Зачем:** гарантирует, что при следующей сборке или на другой машине будут использованы те же версии и те же файлы (защита от подмены и воспроизводимость сборки).
- **Когда появляется:** при первом `go build` / `go mod tidy` / `go get` для модуля. В нашем случае файл был добавлен вручную, чтобы сборка в Docker проходила без предварительного `go mod tidy` на хосте.

**Итог:** `go.mod` — «что нужно», `go.sum` — «какие именно файлы модулей использовались».

## build.sh

```sh
#!/bin/sh
cd /app && go build -o /app/tmp/main ./cmd/send-code
```

- **Что делает:** переходит в `/app` (корень модуля) и собирает пакет `./cmd/send-code` в бинарник `/app/tmp/main`.
- **Зачем:** в контейнере рабочая директория при запуске air может быть другой; скрипт явно задаёт каталог и путь к бинарнику, чтобы сборка всегда шла из корня модуля.
- **Сейчас:** основная сборка идёт через air с аргументом `--build.cmd=go build -o /app/tmp/main ./cmd/send-code`. `build.sh` можно вызывать вручную (например, из контейнера) для отладки или проверки билда без air.

## air.toml

Конфиг [Air](https://github.com/air-verse/air) — утилиты для hot-reload при разработке Go (пересборка и перезапуск при изменении файлов).

| Параметр | Значение | Назначение |
|----------|-----------|-------------|
| `root` | `"/app"` | Корневая директория проекта в контейнере; отсюда смотрятся пути и запускается сборка. |
| `tmp_dir` | `"tmp"` | Каталог для артефактов (бинарник, логи). |
| `[build].pre_cmd` | `["mkdir", "-p", "/app/tmp"]` | Перед каждой сборкой создаётся каталог `/app/tmp`. |
| `[build].entrypoint` | `["/app/tmp/main"]` | Путь к скомпилированному бинарнику (вместо устаревшего `bin`). |
| `[run].cmd` | `"/app/tmp/main"` | Команда запуска приложения после сборки. |

Команда сборки **не** задаётся в toml, а передаётся в Dockerfile через CLI:

```text
CMD ["air", "--build.cmd=go build -o /app/tmp/main ./cmd/send-code", "--build.entrypoint=/app/tmp/main"]
```

Так путь `./cmd/send-code` гарантированно доходит до `go build` (избегаем проблемы с парсингом одной длинной строки в toml).

## Запуск

```bash
docker compose build auth-service
docker compose up -d auth-service
```

Логи:

```bash
docker compose logs -f auth-service
```

Ожидаемый вывод после успешной сборки: `Waiting messages...` — сервис слушает очередь RabbitMQ.
